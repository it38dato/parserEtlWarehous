# Banking ETL & Anti-Fraud DWH Pipeline

ETL-пайплайн на Python и PostgreSQL для ежедневной загрузки банковских данных, ведения хранилища данных (DWH) и формирования витрины мошеннических операций (`REP_FRAUD`).

## 📌 О проекте

Проект реализует полный цикл обработки данных (Extract, Transform, Load):
1. **Извлечение (Extract):** чтение ежедневных выгрузок из файлов (`.txt`/`.csv`, `.xlsx`) и реляционной БД PostgreSQL.
2. **Загрузка в Staging:** очистка стейджинг-слоя и заливка сырых данных.
3. **Трансформация и загрузка в DWH:**
   - Обновление таблиц измерений (поддержка логики SCD1 / SCD2 с техническими полями `create_dt`, `update_dt` / `effective_from`, `effective_to`, `deleted_flg`).
   - Инкрементальная загрузка таблиц фактов.
4. **Построение витрины (`REP_FRAUD`):** поиск мошеннических транзакций по заданным бизнес-правилам и накопление отчетов с привязкой к дате построения (`report_dt`).
5. **Архивация:** переименование обработанных файлов в `.backup` и перемещение в директорию `archive/`.

## 🗄 Архитектура хранилища (Слои данных)

В проекте используется следующая конвенция именования таблиц (где `<CODE>` — персональный 4-буквенный префикс):

* `tuser.<CODE>_STG_<TABLE_NAME>` — стейджинг-слой для первичной загрузки и выделения инкремента.
* `tuser.<CODE>_DWH_DIM_<TABLE_NAME>` — таблицы измерений в формате SCD1 (`terminals`, `cards`, `accounts`, `clients`).
* `tuser.<CODE>_DWH_DIM_<TABLE_NAME>_HIST` — исторические таблицы измерений в формате SCD2 *(опционально)*.
* `tuser.<CODE>_DWH_FACT_<TABLE_NAME>` — таблицы фактов (`transactions`, `passport_blacklist`).
* `tuser.<CODE>_REP_FRAUD` — итоговая витрина с выявленными мошенническими операциями.
* `tuser.<CODE>_META_<TABLE_NAME>` — метаданные загрузок.

## 🔍 Бизнес-логика: Правила выявления фрода

Витрина `REP_FRAUD` фиксирует время события (`event_dt`), данные клиента (`passport`, `fio`, `phone`), тип нарушения (`event_type`) и дату отчета (`report_dt`).

Реализованные сценарии поиска мошенничества:
* ✅ **Просроченный или заблокированный паспорт:** совершение операции клиентом, чей паспорт истек на дату транзакции или числится в черном списке (`passport_blacklist`).
* ✅ **Недействующий договор:** проведение операции по счету с истекшим сроком действия (`valid_to`).
* ✅ **Географическая аномалия:** совершение операций одним клиентом в разных городах в течение 1 часа.
* 🚧 **Попытка подбора суммы** *(в разработке)*: более 3 отклоненных операций подряд с уменьшением суммы в течение 20 минут перед успешной транзакцией.

## 🚀 Установка и запуск

### 1. Клонирование репозитория и настройка окружения
```bash
git clone https://github.com
cd parserEtlWarehous

python3.10 -m venv venv
source venv/bin/activate
pip install pandas psycopg2-binary openpyxl
```

### 2. Инициализация базы данных
Выполните DDL-скрипт для создания всех необходимых таблиц в учебной базе (`edu`):
```bash
psql -U tuser -d edu -f main.ddl
```
*(Примечание: перед запуском убедитесь, что в файле конфигурации/скриптах прописаны актуальные реквизиты доступа к БД).*

### 3. Подготовка данных и директорий
Убедитесь, что папка `archive` существует, а в папку `data` помещены выгрузки за нужные даты (`DDMMYYYY`):
* `transactions_DDMMYYYY.txt`
* `passport_blacklist_DDMMYYYY.xlsx`
* `terminals_DDMMYYYY.xlsx`

### 4. Ручной запуск ETL
```bash
python3 main.py
```
После успешного выполнения обработанные файлы будут перемещены в `archive/` с расширением `.backup`, а результаты появятся в таблице `tuser.<CODE>_REP_FRAUD`.

### 5. Настройка расписания (Cron)
Для автоматического ежедневного запуска добавьте задачу из файла `main.cron` в системный планировщик:
```bash
crontab main.cron
```
